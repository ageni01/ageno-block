# 后续编写规范

## 最短写作流程

1. 运行 `npm run post:new -- 主题 英文文件名 "中文标题"`。
2. 编辑生成的文件；不需要改导航配置。
3. 在 `src/posts/README.md` 对应主题添加文章链接。
4. `npm run dev` 查看效果，再 `npm run build` 检查能否发布。
5. 提交并推送到 main，在 Actions 查看部署结果。

主题参数：`cpp`、`java`、`frontend`、`python`、`unreal`、`ai`、`cli`。新文件名使用小写英文和短横线，例如 `socket-timeout.md`。系列用 `01-xxx.md`、`02-xxx.md`，仅在同一系列目录内编号。

旧目录的大小写和中文名称是历史路径，不要为了统一命名直接改名。未来迁移目录时需要同时处理旧 URL 与内部链接。

## 文章头部

每篇文章开头使用 YAML 元信息，例如：

```yaml
---
title: Java 线程池实践
date: 2026-10-29
category:
  - Java
tag:
  - 线程池
  - 并发
---
```

- `title` 与正文一级标题一致。正文保留一个一级标题，章节从二级标题开始。
- 新文章填实际首次发布日期，格式 YYYY-MM-DD；旧文章未知日期不编造。
- `category` 选择一个大主题：C++、Java、前端、Python、Unreal Engine、AI 应用、命令行。
- `tag` 使用 1–5 个具体关键词；优先复用已有写法。整理时只补了保守的主题标签，后续按内容细化。
- `star` 和 `sticky` 仅对确实需要精选、置顶的文章添加，默认省略。
- 导航页、关于页、示例页设置 `article: false`。

## 正文与资源

开头说明读者能解决什么问题，并写清适用的软件版本。教程应有步骤、可运行示例和验证结果；记录未经验证的推断时明确标注。代码块注明语言，如 java、cpp、bash、yaml。新文章尽量围绕一个问题展开，长系列通过导航列出阅读顺序。

使用 `<!-- more -->` 分隔摘要和正文。引用资料附原始链接。避免复制整篇旧教程形成多个重复版本；新增内容优先更新原文，确有不同定位时在两篇开头说明范围并互相链接。

图片放入 `src/.vuepress/public/assets/images/<文章文件名>/`，例如 `thread-pool/flow.png`，Markdown 引用 `/assets/images/thread-pool/flow.png`。不要把本机绝对路径或有过期签名的临时图片地址放进文章。

文章间优先使用相对 `.md` 链接；含空格的路径编码为 `%20`。新增页面后检查实际预览中的链接。

## 草稿与发布检查

未完成的草稿放在仓库外，准备公开后再用命令创建正式文件。不要依赖 `article: false` 保密：它仅隐藏文章索引，页面仍可能被构建。不要提交密码、密钥、私人数据。

发布前确认：标题与分类正确、示例与图片可用、链接可打开、没有占位文字；构建通过后再 push。部署失败时打开 Actions 的失败步骤查看日志。
